Fix two bugs in the codbdocs core library (packages/core), which is published to
https://cdn.jsdelivr.net/gh/CityofDaytonaBeach/codbdocs@main/packages/core/dist/codbdocs.js

BUG 1 — ReferenceError: pages is not defined (blocks all analysis)
File: the source module that compiles into `extractRelationships(contentGraph, conceptGraph)`
(search for `source_type: "definition"` / the acronym-detection loop).
The acronym/definition pass iterates `for (const page of pages)` but `pages` is never
declared in that scope — the function only receives `contentGraph` and `conceptGraph`.
Any call to load()/analyze() on a real PDF throws before returning a result.
Fix: derive the pages locally from the content graph instead of the phantom variable, e.g.

  const pages = (contentGraph?.pages ?? []).map(p => ({
    pageNum: p.page,
    text: (p.blocks ?? []).map(b => b.text ?? '').join('\n'),
  }));

and keep using page.pageNum / page.text in the loop below. Verify no other function in
the file references an undeclared `pages` (grep for `of pages`, `pages.length`, `pages[`).
Add a regression test that runs a full analyze() on a small fixture PDF and asserts
relationships are returned rather than throwing.

BUG 2 — broken/inconsistent bundle exports
The IIFE/UMD build attaches a nested namespace, so consumers loading the script tag get
`window.CodbDocs.CodbDocs.load` (or `window.CodbDocs.default.load`) instead of
`window.CodbDocs.load`. Every documented example (`CodbDocs.load(file)`) fails with
"CodbDocs.load is not a function".
Fix the bundler output so the browser global is flat: `window.CodbDocs.load`,
`window.CodbDocs.version`, etc. Keep backward compatibility by also assigning
`window.CodbDocs.CodbDocs = window.CodbDocs` and `default`. Ensure the ESM build
exports the same named surface. Add a smoke test that loads dist/codbdocs.js in a
headless browser and asserts typeof CodbDocs.load === 'function'.

Please bump the version and update the README example to match the final global shape.
